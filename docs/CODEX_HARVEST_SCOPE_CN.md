# Codex 自动打票范围与优先级（基于 ranxi v2.7.3 的本地定制）

## 设置入口

系统设置 → Codex 设置 → 自动打票范围：

- **全部 OpenAI 账号**：保留升级前的采集范围。
- **仅指定分组**：可多选 OpenAI 分组，仅采集这些分组内符合条件的账号。
- 指定分组但一个都不选：不进行后台自动采集，**不会回退到全部账号**。
- 跨组选中的同一账号只进入一次候选集合；仍分别为启用的各模型采集。
- 保存后下一轮读取新设置；已经发出的请求不取消。

## 排序规则

依次比较：

1. 账号 `schedulable=true`（后台“参与调度”开关）优先。
2. 账号在选中分组中的关联优先级，数值小的优先。多组选中时取最高优先级（最小值）；全部模式取所有成员关系中的最高优先级。
3. 分组优先级相同，再比较账号自身优先级，数值小的优先。
4. 上述条件均相同的账号/模型使用独立轮询游标；账号ID稳定排序，避免数据库同值排序变化影响公平性。

未参与调度的账号整体排后，即使其优先级数值较小，也不抢占参与调度账号的名额。该规则按开关判断，不以瞬时并发请求数判断。缺少分组优先级的旧快照退回账号自身优先级。

每轮优先扫描前排，只有前排无待探测任务、处于冷却、已有有效票据，或仍有剩余名额时才处理后排。不同优先级桶按顺序完成，同一桶保持并发。前排持续缺票并耗尽配额时，低优先级账号可能长时间等待，这是严格优先策略的取舍。

## 保持不变的行为

- 仅 OpenAI OAuth/setup-token、active、非影子且未限流的账号参与。
- 每轮上限、轮次间隔、单次超时、冷却以及主备票刷新规则不变。
- 有效票据和冷却不会因切换范围/优先级被清空。
- 不改变业务路由、账号分组、调度开关、无票拦截和票据校验。
- 范围外账号不再自动补票，但已有票据照常保留；启用无票拦截时，范围外账号票据过期后仍可能被拦截，不能把采集分组当作路由分组。
- 不承诺提高单次拿票概率，也不修复上游返回312长度导致的拒收。

## API 与日志

沿用管理员设置 GET/PUT：

```json
{
  "openai_codex_ticket_harvest_scope": {
    "mode": "selected",
    "group_ids": [2, 24]
  }
}
```

设置存储为单个JSON值，无数据库结构迁移。省略字段保留原设置；新选择验证正整数ID、分组存在性和OpenAI平台，去重排序。设置读取失败或持久化值损坏时跳过本轮，不擅自扩大为全部采集。

轮次日志保留 `probed`，新增 `schedulable_probed`、`deferred_probed`、`scope`、`selected_groups`。这些是本轮提交探测数，不是成功票数；成功仍看 `harvested`。

旧版程序不会识别新范围设置。回滚旧二进制后，会恢复旧版的全量采集行为；回滚前应先评估是否需要关闭自动打票总开关。
